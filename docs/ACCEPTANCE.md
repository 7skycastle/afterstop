# 완료 기준과 제출할 결과

아래는 앞으로 개발할 앱의 확인 항목이다. 이미 통과한 Android 검사 목록이 아니다. 검증 결과에는 수행 날짜·명령·기기 또는 에뮬레이터·결과를 남긴다.

| 항목 | 확인 방법 |
|---|---|
| 빌드 | Gradle Wrapper를 포함하고 clean debug APK 빌드 명령과 결과 경로 제공 |
| 설치·실행 | 사용 가능한 에뮬레이터 또는 실기기에서 설치·첫 실행 확인. 환경이 없으면 미검증으로 표시 |
| 시연 독립 실행 | 네트워크와 카메라 권한 없이 네 가지 시연 완료 |
| 고속도로 | 감지·프레임·분석 응답·음성 순서가 자동 진행 |
| 터널 | 연기 의심과 이동 어려움 사용자 알림에 따라 안내 변경 |
| 야간 | 관찰 불가 시 위험 없음으로 판단하지 않고 공통 안내 유지 |
| 과속방지턱 | 충격 단독 입력으로 사고 후보를 만들지 않음 |
| 실제 카메라 | 권한 승인·거부·다시 연결·장치 해제를 처리하고 확보된 프레임 표시 |
| 영상 파일 | 정상 영상, 잘못된 파일, 시작·끝 시점의 프레임 확보 확인 |
| 센서 | 단위 변환, 잘못된 값, 시간 역전, 속도 미수신·오래된 값, 중복 이벤트 검사 |
| 버퍼 | 최대 보관 수, 사건 전후 선택, 입력 전환 시 이전 프레임 정리 |
| 서버 | 도달 상태, 인증·허용 정책, 앱과 PC 주소 차이, 요청 취소·시간 초과 확인 |
| 실제 AI | 가능한 환경에서 실제 비전 모델로 요청·응답 확인. 고정 응답 시험과 별도 보고 |
| 응답 검사 | 잘못된 JSON·프레임 번호·근거 부족·이전 요청의 늦은 응답 처리 |
| 음성 | 11개 파일과 문구 일치, 다시 듣기·멈춤·포커스 상실·앱 중단 처리 |
| 사건 기록 | 출처와 미확인 항목 포함, 저장·삭제·내보내기·재실행 확인 |
| 화면 | 휴대폰 세로·태블릿 가로에서 주요 문구 잘림과 조작 영역 확인 |

안전 안내의 실제 정확성, 실차 사고 감지 성능, 현대차 연동, 실제 신고 접수는 위 코드 시험으로 입증되지 않는다. 별도 현장 검증 대상이며 완료 여부를 분리해 보고한다.

## 최종 결과물

1. `android/`: Android 프로젝트 전체, Gradle Wrapper, 앱 리소스, 테스트
2. `backend/`: 수정한 서버와 테스트, 환경 변수 예시, 실행 스크립트
3. `dist/`: 빌드에 성공한 debug APK와 체크섬
4. `docs/RUN_ANDROID_KO.md`: Windows 기준 준비·실행·설치·분석 서버 연결 방법
5. `docs/VERIFICATION.md`: 통과·실패·미검증을 구분한 실제 수행 결과와 재현 명령
6. `docs/DEMO_SCRIPT_KO.md`: 심사자에게 보여줄 1분 제품 시연 순서
7. 가능한 환경에서 직접 캡처한 주요 화면과 시연 영상

실제 실행 화면을 캡처하지 못했으면 화면 그림을 실행 증거로 대신 제출하지 않는다. 확인한 범위를 정확히 보고하고, 남은 작업의 재현 절차를 제공한다.
