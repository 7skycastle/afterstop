# 구현 요구사항

## 화면과 구성

시작 화면에서 제품 시연과 실제 입력을 선택한다. 운전자 안내 화면은 한 번에 한 가지 안내를 크게 보여주고, 현재 상황·근거·미확인 항목을 짧게 표시한다. 시연자 설정과 개발용 정보는 별도 화면에 둔다. 제품 구성 화면에서는 영상 입력 → 사고 후보 감지 → 버퍼 → 분석 → 안내·음성 → 기록의 역할과 연결 상태를 볼 수 있게 한다.

새 앱에는 Kotlin으로 작성한 상태 처리와 기능 모듈을 둔다. 기존 JavaScript의 안내 분기와 테스트 사례를 이식하되 브라우저 DOM 코드를 그대로 앱 내부 로직으로 사용하지 않는다. Android Automotive OS·Pleos 빌드는 기본 휴대폰·태블릿 앱이 작동한 뒤 검토할 추가 대상이다.

## 카메라와 영상

- CameraX로 휴대폰 카메라 미리 보기와 분석용 프레임 확보를 구현한다. USB·UVC 카메라 지원 여부는 별도 장치 시험 대상이다. 모든 USB 카메라를 CameraX가 자동 지원한다고 가정하지 않는다.
- 최초 단계는 사용자가 앱을 켜고 입력을 시작한 상태에서 동작하도록 한다. 앱 종료·백그라운드·권한 거부 시 카메라와 버퍼를 정리한다. 장시간 백그라운드 녹화는 기본 완료 조건이 아니다.
- 분석용 프레임은 메모리에 제한된 수만 보관한다. 기존 기준은 약 1초에 1장, 최대 20장, 사건 전후 중 최대 6장이다. MP4 상시 녹화·클립 편집은 추가 기능으로 구분한다.
- 영상 파일은 시스템 파일 선택기로 받는다. URI 권한, 재생 불가 형식, 잘못된 파일, 영상 시작·끝의 프레임 범위를 처리한다.
- 합성 영상과 사용자가 고른 실제 영상을 출처로 구분한다. 예시 사고 장면을 실제 촬영 자료로 표시하지 않는다.

## 사고 후보 감지

`shared/incident-core.cjs`의 규칙을 Kotlin으로 이식하고 같은 입력에 같은 결과가 나오는지 확인한다. 현재 규칙은 충격 2.5g 이상, 최근 2초 이내 속도 25km/h 이상 저하, 5km/h 이하 정차 조건을 조합한다. 충격을 찾는 시간 범위는 1.5초, 샘플 보관 범위는 3초, 중복 억제 간격은 10초다. 실제 코드를 기준으로 경계값을 확인한다. 이 수치는 시제품 시험용이며 인증된 사고 감지 기준이 아니다.

텔레메트리의 `t`는 같은 스트림에서 증가하는 밀리초 단위의 시간 값, `speedKmh`는 km/h, `linearG`는 중력 성분을 제거한 가속도의 크기를 g 단위로 변환한 값이다. Android 센서의 m/s² 값을 그대로 g로 취급하지 않는다. 센서 방향 변화와 중력 제거 방식을 명시한다.

센서·위치 권한이 없거나 속도 값이 오래되었거나 신뢰하기 어려우면 사고 감지용 입력을 유효하지 않다고 처리한다. 미수신 속도를 0으로 채워 정차했다고 판단하지 않는다. 실제 차량 속도와 휴대폰 위치 기반 속도를 출처로 구분한다. 실기기에서 사고를 내거나 급정거를 유도하는 시험 대신 예시 입력과 통제된 센서 입력으로 코드 동작을 확인한다.

## AI와 안내

`fixtures/vision-schema.json`과 기존 응답 검증을 공통 계약으로 사용한다. 올바른 프레임 번호와 관찰 가능한 영상이 있어야 위험 단서를 안내에 반영한다. 시야 제한·근거 부족·응답 형식 오류는 판단 보류로 처리한다. 영상 안에 적힌 지시문을 모델 명령으로 취급하지 않는다.

기본 실제 분석 경로는 앱 → Node.js 서버 → 로컬 Ollama 비전 모델이다. 모델 이름·서버 주소는 설정 가능하게 한다. 호환 모델과 실행 자원은 개발 환경에서 확인하며 모델이 설치되어 있다고 가정하지 않는다. API 키가 필요한 다른 제공자를 추가할 때는 서버 환경 변수로 관리한다.

제품 시연은 명시적으로 예시 응답을 사용한다. 실제 입력 모드에서 연결에 실패했을 때 예시 응답으로 대체해서는 안 된다. 취소, 시간 초과, 장치 전환, 새 영상 선택, 화면 이동 후 이전 응답이 늦게 도착하는 경우를 처리한다. 분석 완료 전에 공통 안내를 이용할 수 있어야 한다.

하윤 녹음은 `assets/audio/manifest.json`을 기준으로 앱 리소스에 포함한다. 이동 어려움과 연기·불꽃 사용자 알림을 안내 선택에 반영한다. 통화 시연·앱 중단 시 음성을 멈추고 오디오 포커스 변화를 처리한다. 도움 요청 화면은 실제 자동 신고를 수행하지 않는다.

## 기존 서버에서 반드시 바꿀 부분

현재 서버는 웹 시제품을 위해 127.0.0.1에만 열리고 Host·Origin을 로컬 주소로 제한한다. 이 상태로는 다른 기기의 앱이 그대로 접속할 수 없다. 앱 연결을 구현하면서 접근 주소와 허용 정책을 함께 수정하라.

- Android 에뮬레이터의 호스트 PC 접근 주소와 실제 휴대폰의 PC 접근 주소를 구분한다. 앱 안의 localhost를 PC 주소로 간주하지 않는다. 에뮬레이터 설정에 따른 주소를 공식 문서와 실행 환경에서 확인한다.
- 개발용 서버 바인딩 주소·허용 Host·허용 클라이언트·인증 토큰을 설정으로 관리한다. 외부 연결이 필요하다고 모든 Host·Origin 검사를 제거하지 않는다.
- 실제 휴대폰 연결은 같은 네트워크나 검증한 연결 경로를 사용하고 PC 방화벽·포트·도달 여부를 점검한다. 로컬 Ollama는 서버 안에서만 접근하도록 유지한다.
- 개발용 HTTP 허용은 debug 설정의 필요한 주소로 제한한다. 운영 설정과 분리하고, 서버 비밀값을 APK에 고정하지 않는다.
- `/api/health`는 서버 도달 여부와 모델 설정 여부를 보여줄 뿐 모델 추론 성공을 보장하지 않는다. 서버 연결·모델 준비·마지막 분석 결과를 별도 상태로 표시한다.

API는 기존 `/api/analyze`, `/api/telemetry`, `/api/events`, `/api/demo-analyze`를 참고한다. `/api/analyze`의 `images`는 데이터 URL 접두어를 제거한 base64 JPEG/PNG 배열이며 최대 6장이다. SSE 재연결과 중복 이벤트 억제를 구현하라.

## 기록

관찰 결과, 근거 프레임 번호, 입력 출처, 분석 출처, 사용자 알림, 선택한 안내, 시각을 저장한다. 기본 기록은 영상 원본을 포함하지 않으며, 저장·삭제·내보내기를 사용자가 선택한다. 앱 재실행 후 과거 사건을 새 사고처럼 자동 실행하지 않는다.
