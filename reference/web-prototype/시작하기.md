# 멈춘 다음 · 블랙박스 AI 안내

사고 직후 운전자가 메뉴를 찾지 않아도 영상 확보, 장면 분석, 음성 안내가 이어지는 제품 구성을 보여주는 시제품입니다.

## 바로 시연하기

`멈춘다음_시뮬레이션.html`을 Chrome 또는 Edge에서 엽니다. 서버와 모델 설치 없이 **전체 흐름 시연**을 누르면 실행됩니다. 소리가 나지 않으면 차량 화면의 **다시 듣기**를 눌러 주세요.

1. 고속도로: 주행 신호 → 사고 후보 감지 → 전후 장면 확보 → 분석 응답 → 하윤 음성 안내
2. 터널: 연기 의심 단서가 있는 응답에 따라 안내 선택
3. 야간: 영상 품질이 부족하면 위험 여부 판단을 보류하고 공통 안내 유지
4. 과속방지턱: 충격이 있어도 속도 저하·정차 조건이 맞지 않으면 사고 안내로 전환하지 않음

**제품 구성** 탭에서 영상 입력, 감지 코드, 영상 버퍼, 분석 서버, 안내 선택, 사고 기록의 실행 범위를 확인할 수 있습니다. **기록 받기**는 영상 자체를 제외한 시연 처리 기록을 JSON으로 저장합니다.

시연의 도로 장면은 합성 그림이며 차량 신호와 AI 분석 응답도 예시입니다. 시연 응답은 실제 모델 추론 결과가 아닙니다. 하윤 음성 11개는 파일에 포함되어 있습니다. 실제 통화·신고는 하지 않습니다.

## 로컬 프로그램 실행

Node.js 22 이상이 필요합니다. 외부 npm 패키지를 설치하지 않습니다.

Windows에서는 압축을 푼 뒤 `start-windows.bat`을 실행합니다. 또는 이 폴더에서 아래 명령을 실행합니다.

```sh
node server.cjs
```

브라우저에서 http://localhost:8787 을 엽니다. 종료하려면 서버 창에서 Ctrl+C를 누릅니다.

### 실제 영상과 모델 연결

1. 제품 화면에서 **실제 입력 연결**을 선택합니다.
2. 보유한 블랙박스 파일을 선택하거나 브라우저 카메라 권한을 허용해 USB·전용 카메라를 연결합니다.
3. 파일의 사고 시점으로 이동한 뒤 **사고 전후 프레임 확보**를 누릅니다. 실제 카메라는 최근 프레임을 임시 보관합니다.
4. 별도로 Ollama를 실행하고 영상 입력과 구조화 출력을 지원하는 비전 모델을 준비합니다. 이 패키지에는 모델과 가중치가 없습니다.
5. **실제 AI 실행 환경 연결**에서 주소를 `http://localhost:8787/api/chat`으로 두고 설치한 모델 이름을 입력합니다. 프레임 전송에 동의한 뒤 분석을 요청합니다.

서버는 고정된 로컬 Ollama 주소로 분석을 전달합니다. 다른 로컬 주소가 필요하면 실행 전에 `OLLAMA_URL`을 설정합니다. 모델 이름을 서버에서 고정하려면 `VISION_MODEL`을 설정합니다. 서버는 모델 준비 상태를 자동으로 보장하지 않으며 모델이 없거나 오류가 나면 결과를 만들지 않습니다.

직접 HTML을 열어도 시연과 지원 브라우저의 파일 처리를 사용할 수 있습니다. 카메라·분석 서버·이벤트 연결은 localhost에서 실행하는 편이 적합합니다. 서버는 127.0.0.1에만 열리고, 브라우저의 분석·신호 입력 요청에는 같은 출처 정책을 적용합니다. 운영 배포용 인증·암호화·접근 제어는 포함하지 않습니다.

### 차량 신호를 자동 처리하기

로컬 화면의 **실제 입력 연결 → 로컬 사고 이벤트 수신 연결**을 누릅니다. 카메라 또는 영상 파일을 먼저 연결하고 AI 설정을 마치면, 서버에서 사고 후보 이벤트를 받으면 영상 확보와 분석 요청이 이어집니다. 분석 설정이 없어도 공통 안내는 실행됩니다.

서버의 `POST /api/telemetry`에 아래 형식으로 차량 신호를 넣습니다. `t`는 같은 스트림 안에서 계속 증가하는 밀리초 단위의 시간 값, `speedKmh`는 km/h, `linearG`는 중력을 제거한 가속도의 크기를 g 단위로 표현한 값입니다.

```json
{"streamId":"camera_unit_01","samples":[{"t":100,"speedKmh":72,"linearG":0.04,"source":"external_telemetry"}]}
```

같은 `streamId`의 신호는 이어서 처리합니다. 재생을 처음부터 시작할 때는 새 ID를 쓰세요. ID가 없으면 요청 한 건 안에서만 판정합니다. 샘플은 시간순이어야 하며, 한 요청은 최대 2,000개입니다. 스트림은 최대 8개, 5분 동안 입력이 없으면 정리합니다.

화면과 서버 연결만 시험하려면 별도 터미널에서 다음을 실행합니다.

```sh
node send-demo-telemetry.cjs
```

이 명령은 실제 센서를 읽지 않고 `synthetic_fixture`로 표시한 신호를 전송합니다. 감지 코드는 충격 2.5g 이상, 최근 2초 이내 속도 25km/h 이상 저하, 5km/h 이하 정차 조건을 조합합니다. 중복 이벤트를 억제하지만, 이 수치는 실차에서 보정한 사고 판정 기준이 아닙니다. 충격 단독 입력이나 영상만으로 사고 여부를 확정하지 않습니다.

## 구성 파일

| 파일 | 역할 |
|---|---|
| 멈춘다음_시뮬레이션.html | 서버 없이 실행하는 제품 시연, 실제 영상·카메라 입력, 음성 11개 |
| server.cjs | 로컬 화면 제공, 사고 후보 이벤트, 예시·실제 모델 분석 API |
| shared/incident-core.cjs | 시연·서버가 공통으로 쓰는 감지 규칙과 영상 버퍼 |
| shared/vision.cjs | 영상 분석 응답 검사와 안내 선택 규칙 |
| send-demo-telemetry.cjs | 예시 차량 신호를 서버에 넣는 연결 시험 |
| tests/ | 감지·판단 보류·서버 API 시험 |

실제 모델 API는 Ollama의 `/api/chat`, 이미지 입력, JSON Schema 응답 형식을 사용합니다. 참고: https://docs.ollama.com/api/chat · https://docs.ollama.com/capabilities/vision

## 확인한 범위

감지 조건, 충격 단독 입력 제외, 중복 억제, 잘못된 신호 거부, 버퍼 범위, 근거 없는 위험 추정 보류, 로컬 API와 이벤트 전달을 시험했습니다. 모델 연결 시험에는 응답을 고정한 테스트 서버를 사용했습니다. UI 코드의 네 가지 시연 흐름, 탭 전환, 취소, 음성 재생 요청도 DOM·캔버스 시험으로 확인했습니다.

이 환경에서는 브라우저의 최종 화면·오디오 출력, 실제 카메라·차량 센서·비전 모델 추론을 검증하지 못했습니다. 현대차의 빌트인 캠 API, 사고 신호, SOS를 사용하거나 연결한 상태가 아닙니다. 차량 제조사가 허용하는 입력부를 확보하면 현재의 영상·차량 신호 규격으로 변환하는 어댑터를 붙이는 구조입니다. 실제 운전자에게 적용하기 전에는 감지 오류·영상 누락·지연과 안내 내용의 현장 검증이 필요합니다.
